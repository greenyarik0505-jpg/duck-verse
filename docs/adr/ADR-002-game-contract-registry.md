# ADR-002: Єдиний контракт ігор та валідація реєстру (SCRUM-40)

## Статус
Прийнято (Accepted)

## Контекст
У початковій версії платформи Duck Verse конфігурація `GAME_REGISTRY` містила лише базові поля (`id`, `title`, `enginePath`, `engineClass`). Опис керування (`controls`), підрахунок очок (`scoring`) та особливості запуску рушіїв (Canvas, React, DOM) були фрагментовані або захардкоджені всередині компонента `GameModal.jsx`. Це створювало ризики:
1. Помилки при додаванні нової гри виявлялися лише під час рантайму в браузері.
2. Не було контролю за унікальністю `id` або коректністю категорій/статусів.
3. Доступність (a11y) та підказки керування не були пов'язані з реєстром.

## Рішення
1. **Створення модуля контракту (`lib/games/contract.js`)**:
   - Визначено допустимі множини: `ALLOWED_CATEGORIES`, `ALLOWED_STATUSES`, `ALLOWED_ENGINE_TYPES`.
   - Реалізовано функцію `validateGameContract(game)` для суворої перевірки структури.
   - Реалізовано функцію `validateGameRegistry(registry)` для перевірки цілісності та відсутності дублікатів ідентифікаторів.
2. **Збагачення `GAME_REGISTRY` (`lib/games/registry.js`)**:
   - Кожна гра отримує поля: `engineType`, `controls` (summary, keyboard, mouse, touch), `scoring`, `accessibility`.
   - Виклик `validateGameRegistry(GAME_REGISTRY)` відбувається при ініціалізації модуля, що зупиняє білд у разі дефекту.
3. **Рефакторинг `GameModal.jsx`**:
   - Прибрано розгалуження `if (currentGameId === 'geometry_dash') ...` для підказок керування; тепер текст береться з `gameMeta.controls.summary`.
   - Визначення типу гри базується на `gameMeta.engineType`.
4. **Контрактні тести (`tests/game_registry.test.mjs`)**:
   - Автоматизовані тести перевіряють офіційний реєстр, відхилення дублікатів та некоректних полів.
   - Тести інтегровано в `npm test`.

## Наслідки
- **Позитивні**:
  - Нульова ймовірність тихого збою при додаванні нової гри.
  - Повна типізація метаданих керування та доступності.
  - Чітка інструкція для розробників (`docs/GAME_INTEGRATION_GUIDE.md`).
- **Негативні**:
  - Додавання нової гри вимагає заповнення всіх обов'язкових контрактних полів (що водночас є запобіжником якості).
