# ADR-001: Архітектура модульного реєстру Duck Academy (Curriculum Registry)

- **Статус**: Прийнято (Approved)
- **Дата**: 2026-09-16
- **Автор / Власник**: Yarik0505 (Team Lead)
- **Jira Issue**: [SCRUM-56](https://gta6-sliv-cyberleek.atlassian.net/browse/SCRUM-56)
- **Контекст**: Duck Verse Game Hub & Academy

---

## 1. Контекст та постановка проблеми (Context)

Проект **Duck Verse** розвивається з ігрового хабу в комплексну освітньо-інженерну платформу **Duck Academy**. Для забезпечення масштабування платформи виникла необхідність:
1. Організувати уроки, навчальні треки та передумови (prerequisites) у вигляді єдиного джерела правди (Single Source of Truth), замість розкидання логіки по окремих React-компонентах чи базах даних.
2. Гарантувати, що новий урок або модуль не може бути доданий без дотримання суворого контракту (обов'язкові Acceptance Criteria, Evidence Types, зв'язок із Jira-ключами).
3. Унеможливити появу циклічних залежностей між уроками, через які учень міг би застрягти у замкненому колі вимог.
4. Забезпечити ізоляцію освітнього функціоналу під Feature Flag, щоб наявний ігровий хаб (Geometry Dash, Neon Hacker, Galactic Invaders, Quack Clicker) працював абсолютно безвідмовно.

---

## 2. Прийняте рішення (Decision)

1. **Модульний типізований реєстр (`lib/academy/registry.js`)**:
   - Навчальна програма формується у вигляді декларативного реєстру `CURRICULUM_REGISTRY`.
   - Кожен елемент реалізує строгий контракт `LessonContract`:
     - `id`: унікальний рядковий ідентифікатор.
     - `jiraKey`: прямий зв'язок із задачею в Jira (наприклад, `SCRUM-56`, `SCRUM-54`).
     - `trackId`: прив'язка до одного з 3 базових треків (`track-frontend-gaming`, `track-devsecops`, `track-ai-safety`).
     - `level`: числовий рівень складності (Level 0 – 9).
     - `prerequisites`: масив ID уроків, які мають бути успішно здані для відкриття поточного уроку.
     - `acceptanceCriteria`: обов'язкові критерії успіху.
     - `requiredEvidence`: типи свідоцтв про виконання (`github_pr`, `jira_issue`, `test_run`, `mentor_review`).

2. **Автоматична валідація на етапі компіляції (Build-time DAG Validation)**:
   - Функція `validateCurriculumRegistry()` запускається під час імпорту модулів та в юніт-тестах.
   - Використовує алгоритм пошуку в глибину (DFS) для перевірки відсутності циклів (Directed Acyclic Graph).
   - Якщо знайдено дублікат ID, відсутній prerequisite або циклічна залежність — збірка Next.js (`npm run build`) негайно блокується з детальним повідомленням про помилку.

3. **Ізоляція через Feature Flag (`lib/academy/config.js`)**:
   - Доступ до модуля Академії контролюється через прапорець `FEATURE_ACADEMY_ENABLED` (змінна оточення `NEXT_PUBLIC_FEATURE_ACADEMY`).
   - Якщо прапорець вимкнено, маршрути Академії безпечно приховані, не впливаючи на ігри та користувачів хабу.

4. **Незалежність від AI-провайдерів (Provider-Agnostic Design)**:
   - Контракти оцінювання та рецензування завдань оперують абстрактними подіями `ProgressEvent` та `EvidenceRecord`. Вони можуть оброблятися ментором-людиною, локальними скриптами автоматичного тестування або будь-якою обраною LLM-моделлю без жорсткої прив'язки до конкретного вендора.

---

## 3. Наслідки (Consequences)

### Позитивні:
- **Передбачуваність та якість**: Будь-яка помилка в налаштуванні уроків чи залежностей виявляється локально ще до коміту та пушу в репозиторій.
- **Масштабованість**: Додавання нового курсу чи уроку зводиться до додавання одного конфігураційного об'єкта в реєстр.
- **Прозорість для учня**: Граф передумов чітко пояснює учневі, які знання потрібні перед початком завдання.
- **Аудитованість**: Кожен урок прямо пов'язаний із задачею Jira, що відповідає вимогам треку DevSecOps Governance.

### Компроміси (Trade-offs):
- Потрібна обов'язкова дисципліна команди щодо збереження унікальних ID та правильного заповнення критеріїв прийняття.

---

## 4. План зворотної сумісності та міграцій (Backward Compatibility & Migration)

1. **Версіонування**: Реєстр має поле `schemaVersion: '2026.1'`. Будь-які зміни в сигнатурі полів реєстру вимагають інкременту версії.
2. **Депрекація**: У разі вилучення уроку його статус змінюється на `'deprecated'` без видалення його ID, щоб не ламати історію прогресу учнів, які його завершили.
