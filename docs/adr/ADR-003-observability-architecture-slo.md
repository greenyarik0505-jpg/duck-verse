## 1. Контекст та постановка проблеми (Context & Problem Statement)

Зі зростанням складності Duck Verse неструктуровані `console.log` виклики стають неефективними, не дозволяють відстежувати наскрізний шлях запиту, створюють ризик витоку персональних даних (PII) у логи хостингу та не дають чіткого сигналу про порушення стабільності користувацького досвіду.

Необхідно впровадити:
1. **Єдиний формат структурованого логування** з Correlation ID та версією релізу.
2. **Систему цілей рівня обслуговування (SLI/SLO)**: Availability (99.9%), Latency (< 150ms p95), Canvas 60 FPS, Auth Security.
3. **Розрахунок бюджету помилок (Error Budget)** та швидкості його спалювання (Burn Rate).
4. **Оповіщення з правилами анти-шуму (Anti-Noise Rules)** та прив'язкою до Runbooks.

---

## 2. Критерії оцінки рішення (Decision Drivers)

1. **Безпека та приватність (Zero PII in Logs)**: Логи не повинні містити паролів, токенів чи імен учнів.
2. **Продуктивність**: Логування та збір метрик не повинні сповільнювати виконання запитів (< 1ms на операцію запису).
3. **Операційна цінність (Actionable Alerts)**: Кожен алерт повинен супроводжуватися конкретною інструкцією з усунення (Runbook).
4. **Вартість та оверхед (Zero Third-Party Cost)**: Модуль має працювати на базі Vercel Edge Logs та автономного in-memory агрегатора без платного Datadog/NewRelic на поточному етапі.

---

## 3. Специфікація SLI / SLO Duck Verse

| Категорія | SLI (Індикатор) | SLO (Цільовий показник) | Error Budget (на 30 днів) | Runbook |
| :--- | :--- | :--- | :--- | :--- |
| **Availability** | Успішні відповіді HTTP 2xx/3xx | **99.9%** | 0.1% (до 43 хв простою) | `RUNBOOK-01-API-OUTAGE` |
| **Latency** | Час відповіді Route Handlers (p95) | **< 150ms** | 5% повільних запитів | `RUNBOOK-02-LATENCY-SPIKE` |
| **Gaming FPS** | Частота кадрів Canvas 2D рушія | **99% фреймів >= 55 FPS** | 1% просідань нижче 55 FPS | `RUNBOOK-03-CANVAS-FPS-DROP` |
| **Auth Security** | Неперехоплені спроби ескалації/IDOR | **100% заблоковано (0 витоків)** | 0% толерантності | `RUNBOOK-04-SECURITY-BREACH` |

## 5. Розглянуті варіанти

### Варіант А: Зовнішній платний SaaS APM (Datadog / NewRelic)
- **Відхилено**: Невиправдані щомісячні фінансові витрати для студентського/open-source проекту.

### Варіант Б: Звичайні console.log без схеми
- **Відхилено**: Відсутність можливості автоматизованого моніторингу та кореляції помилок.

### Варіант В (ОБРАНО): Вбудований автономний модуль структурованих метрик та SLO дашборду
- **Переваги**: Нульова вартість, повний контроль за PII, миттєвий підрахунок Error Budget у режимі реального часу, відкриті Runbooks для учнів Академії.
