## 📌 1. Призначення регламенту

Цей документ визначає обов'язковий інженерний бар'єр (Quality Gate), який повинна пройти будь-яка зміна перед злиттям у гілку `main` та деплоєм на продакшн Vercel (`duck-verse.vercel.app`). Реліз вважається недійсним без надання доказів (Evidence Links) та схвалення відповідального ментора для ризикових змін.

---

## 📋 2. Шість обов'язкових гейтів якості (The 6 Quality Gates)

Кожен реліз повинен отримати 100% підтвердження за шістьма категоріями:

| № | Гейт якості | Обов'язкові критерії перевірки | Інструмент / Команда |
| :--- | :--- | :--- | :--- |
| **1** | **PR Review Gate** | - Мінімум 2 схвалення (Approve) від колег/ментора<br>- Відсутність незакритих коментарів (Conversations resolved)<br>- Відповідність формату Conventional Commits із ключем Jira (`feat(SCRUM-XX)`). | GitHub Pull Requests |
| **2** | **CI Pipeline Gate** | - Чистий лінтинг (`0` warnings, `0` errors)<br>- Успішна компіляція Next.js (всі 39+ маршрутів)<br>- 100% проходження тестів (`npm test`). | `npm run lint`<br>`npm run build`<br>`npm test` |
| **3** | **Security & Privacy Gate** | - Відсутність секретів, токенів та паролів у комітах<br>- Активний PII Shield (захист даних дітей за COPPA/GDPR-K)<br>- `0` вразливостей високого/критичного рівня у залежностях. | `npm audit`<br>PII Sanitizer |
| **4** | **Accessibility & UX Gate** | - Повна адаптивність під мобільні екрани (360px..1920px)<br>- Наявність семантичних HTML-тегів та ARIA-атрибутів<br>- Зрозумілі для дітей та батьків формулювання повідомлень. | Chrome DevTools CDP<br>Screen Reader Check |
| **5** | **Performance & SLO Gate** | - 60 FPS для ігрових рушіїв Canvas 2D<br>- P95 затримка API не перевищує 250 мс<br>- Відсутність витоків пам'яті у React компонентах. | SLO Observer<br>Headless Chrome |
| **6** | **Rollback & Runbook Gate** | - Наявність чіткої інструкції швидкого відкату (Revert PR)<br>- Зворотна сумісність збережених даних / схем API<br>- Відсутність деструктивних незворотних міграцій. | Rollback Runbook |

## ⚠️ 3. Класифікація ризиків та матриця схвалення (Change Approval)

Кожна зміна класифікується за рівнем ризику:

- 🟢 **LOW_RISK** (Виправлення опечаток, стилі, оптимізація текстів):
  - Потрібно: 6 гейтів якості + звичайне рев'ю.
- 🟡 **MEDIUM_RISK** (Нові уроки, доповнення каталогу ігор, нові тести):
  - Потрібно: 6 гейтів якості + 2 схвалення PR.
- 🔴 **HIGH_RISK** (Зміни сесій, ролей, Scores API, взаємодія з Jira, AI Safety):
  - **ОБОВ'ЯЗКОВО**: Явне погодження ментора (Explicit Mentor Approval) з підтвердженням у Jira.
- 🚨 **CRITICAL** (Архітектурні рефакторинги, міграції бази даних, видалення даних):
  - **ОБОВ'ЯЗКОВО**: Подвійний підпис: Team Lead + Провідний інженер.

## 📎 4. Обов'язкові докази готовності (Evidence Links)

Релізний запис **не може бути переведений у стан `READY`** без наявності 4 обов'язкових посилань:
1. **Pull Request URL**: Пряме посилання на злитий або відкритий PR у репозиторії.
2. **Jira Issue Key**: Ключ задачі у форматі `SCRUM-XX`.
3. **CI / Test Evidence**: Протокол успішного виконання тестів (100% pass rate).
4. **Live Verification Artifact**: Знімок екрана перевірки живого середовища (`live_*.png`).
